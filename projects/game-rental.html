Game Rental Database System

SQL Server backend for game rental management application

Entity Relationship Diagram

7-table relational model supporting:

  • User role separation (Admin/Customer)
  • Game inventory tracking
  • Rental transaction history
  • Vendor relationships

Database Schema

Core Tables

Table Purpose Relationships
Account Base user credentials Parent to Customer/Admin
Game Game catalog Linked to Admin (vendor)
Rent Active rentals Links Customers to Games

Key Constraints

CREATE TABLE Account ( ACC_ID INT IDENTITY(1,1) PRIMARY KEY, Username VARCHAR(55) UNIQUE NOT NULL, Password VARCHAR(55) NOT NULL, E_mail VARCHAR(55) UNIQUE NOT NULL, Name VARCHAR(55) NOT NULL ); CREATE TABLE Rent ( rent_id INT IDENTITY(1,1) PRIMARY KEY, S_Date DATE NOT NULL, E_Date DATE NOT NULL, Game_ID INT FOREIGN KEY REFERENCES Game(Game_ID), ACC_ID INT FOREIGN KEY REFERENCES Customer(ACC_ID) );

Business Logic Implementation

1. Account Hierarchy

-- Inherited customer/admin roles CREATE TABLE Customer ( ACC_ID INT PRIMARY KEY, Age INT NOT NULL, Phone VARCHAR(55) NOT NULL, FOREIGN KEY (ACC_ID) REFERENCES Account(ACC_ID) ON DELETE CASCADE );

2. Rental Analytics

-- Most rented game SELECT TOP 1 g.Title, COUNT(r.rent_id) AS rental_count FROM Game g JOIN Rent r ON g.Game_ID = r.Game_ID GROUP BY g.Title ORDER BY rental_count DESC;
